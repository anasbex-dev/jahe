# JAHE 0.8 specification decisions needed

This note records design questions that block sound implementation. It does not amend the approved language specification. Recommendations are proposals for approval.

| Topic | Exact ambiguity | Available alternatives | Recommended choice | Compatibility impact / tests |
|---|---|---|---|---|
| Forward constant references | The design defines compile-time `const`, but does not say whether a constant initializer may name a later declaration. | Permit dependency-ordered references across a module; or require earlier declarations only. | Require earlier declarations initially. This matches lexical declaration visibility and avoids adding a module-wide dependency-resolution rule. | Permitting later references could make currently rejected programs valid and requires dependency graph evaluation. Tests: forward reference accepted/rejected, cycles, unknown names, shadowed local constants. Current compiler resolves only earlier declarations and diagnoses cycles. |
| Character ordering | `char` is a Unicode scalar, but relational ordering is not specified. | Compare Unicode scalar numeric values; or reject `< <= > >=`. | Reject relational operators until chosen. | Enabling order accepts programs currently rejected. Tests should cover ASCII and multibyte scalars and establish ordering model. Current compiler rejects ordering. |
| Character casts | No allowed source/target types or invalid-scalar conversion behavior are specified. | Disallow casts; permit checked `char`↔`u32`; or provide named conversion APIs. | Keep casts unsupported; prefer explicit checked conversion APIs if later required. | Adding casts expands valid programs and must define invalid scalar errors. Current compiler rejects casts. |
| Floating remainder | The operator inventory includes `%` but does not settle whether it applies to floats or define IEEE remainder versus truncating remainder. | Keep `%` integer-only; define floating `%` as `fmod`-style remainder; or define IEEE remainder. | Keep `%` integer-only. | A later rule changes accepted programs and potentially results. Current compiler rejects float remainder. |
| Integer overflow in constant evaluation | The design says integer arithmetic is checked, but does not specify whether a failing constant initializer is a compile-time diagnostic or a compile-time panic/error value. | Reject during compilation; or preserve a runtime trap even when operands are constant. | Reject during compilation with an overflow diagnostic. | Compile-time rejection is safer and consistent with constant evaluation. Tests need each signed/unsigned boundary, including min/-1 and shifts. Runtime operations currently trap on checked overflow. |
| `never` flow and unreachable code | `never` is described as no values and non-returning, but no general proof rule, unreachable-code policy, or loop termination proof is defined. | Recognize syntactic divergence only; use conservative CFG reachability; or attempt general termination proof. | Define `never` by control-flow reachability: a path returning normally cannot satisfy `never`; unreachable statements after guaranteed termination are diagnosed or explicitly allowed by a separate rule. Avoid general program termination proofs. | Could reject or newly accept functions depending on exact reachability policy. Tests should cover both branches diverging, one branch returning, infinite loops, calls to never functions, and code after termination. Current compiler handles a limited set only. |

## Implementation status

- The IR `Constant` payload remains intentionally type-neutral, but the compile-time evaluator wraps it in `TypedConstant { ty, value }`. It carries integer width/signedness and target pointer width, masks integer payloads to the active width, and keeps f32 values rounded at each operation boundary.
- Constant failures now use structured categories and source locations for overflow, underflow, division by zero, signed minimum divided by -1, invalid shifts, out-of-range casts, invalid typed operations, unknown dependencies, cycles, and unsupported expressions.
- Targeted regression coverage now exercises wide compound integers, integer endpoints, f32 rounding, f64 precision and IEEE special values, native linking/execution, and operation-specific diagnostics. Exhaustive operation/cast parity matrices remain unfinished.
- Current `never` handling recognizes exact `while true` and never-returning calls. It is not a complete reachability analysis and does not settle unreachable-code behavior.

Until these issues are addressed and tested, scalar conformance remains **PARTIAL**.
